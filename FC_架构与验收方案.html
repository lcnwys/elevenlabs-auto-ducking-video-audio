02 / FC 任务协议：只传小 JSON，不传视频字节

云端建议使用统一 job_id；业务后端只向 FC 提交存储对象 key 和混音参数。不要通过同步调用体直接上传上百 MB 的视频。已完成的 fc_worker.py 是本地同构执行器，验证 FFmpeg 模块可以脱离业务后端运行。

{
  "job_id": "dck_20261024_a1b2c3",
  "bucket": "your-private-media-bucket",
  "video_key": "jobs/dck_20261024_a1b2c3/source.mp4",
  "music_key": "jobs/dck_20261024_a1b2c3/music.mp3",
  "output_key": "jobs/dck_20261024_a1b2c3/results/output.mp4",
  "speech_segments": [
    {"start": 1.00, "end": 3.40},
    {"start": 4.50, "end": 7.65}
  ],
  "mix": {
    "reduction_db": 16,
    "normal_music_db": -12,
    "pre": 0.15,
    "post": 0.25,
    "attack": 0.15,
    "release": 0.55
  }
}

约定执行过程

状态动作输出或恢复策略
queued保存任务元信息并触发 FC 异步任务立即返回 job_id，不阻塞浏览器
running校验对象 → 下载到 /tmp → FFmpeg → 上传 OSS落日志与处理耗时；限制超时和临时磁盘
succeeded输出完成后保存 metadata给客户短时签名 URL
failed记录错误码、排查日志有限重试、幂等检查、失败告警

FC 侧输入协议属于本方案设计，并非阿里云原生标准接口。真实部署时需实现 OSS 下载/上传适配器、任务状态持久化和 FC handler。

03 / 阿里云函数计算选型与初始配置

配置项建议首轮试验值原因 / 调整依据
部署地域优先东京 ap-northeast-1 或新加坡 ap-southeast-1韩国首尔暂不支持自定义容器和异步任务；OSS 尽量与 FC 同地域
函数类型异步任务 / Task Function音视频处理耗时不稳定，避免浏览器长时间挂起
运行时Custom Container（或自带 FFmpeg 的 Runtime）可锁定 FFmpeg 版本、编码器及运行依赖
首选规格1 vCPU / 2 GB 内存仅做第一轮 15–60s 视频基准测试，不作为最终承诺
临时磁盘512 MB；大文件改 10 GB同时容纳输入视频、配乐、临时音频及成品文件
并发每实例 1 个混音任务先隔离 CPU 和内存，后根据测试提高并发
超时首轮 300 秒应根据压测 P95 和 10 分钟最大素材做调整；非平台上限
保温最小实例数为 0使低请求量场景更贴合按调用付费；需接受冷启动
权限独立 RAM 角色，最小 OSS Get/Put 权限密钥在业务后端，FC 不保存 ElevenLabs Key

官方当前列出的 FC CPU 实例上限包括 32 GB 内存、最长 86,400 秒执行时间，以及 512 MB/10 GB 临时磁盘选项；这些是平台上限，不代表推荐把任务设置到上限。Custom Container 文档注明仅支持 AMD64 镜像，Mac Apple Silicon 上构建时应使用 linux/amd64。来源：FC 资源限制、自定义容器。

推荐存储目录

jobs/{job_id}/source.mp4
jobs/{job_id}/music.mp3
jobs/{job_id}/transcript.json
jobs/{job_id}/segments.json
jobs/{job_id}/results/output.mp4

存储桶应设为私有，上传采用短时授权，成品下载使用签名 URL；对象生命周期默认按业务需要设置，例如 24–72 小时，避免长期累积。OSS 触发器不是必须：业务后端已有明确“开始混音”动作时，直接创建 FC 异步任务更易管理。若使用 OSS 事件触发，必须限定 jobs/*/ready/ 前缀，避免输出文件再次触发递归处理。

04 / 成本评估与压测路线

不建议现在直接给客户承诺每分钟处理成本。 函数计算按 vCPU 使用量、内存使用量、调用次数等计费，还需计算 OSS 存储、传输与公网流量。音视频编码的耗时取决于编码器、视频长度、分辨率，以及视频能否 stream copy。

FC 处理费用 ≈ vCPU 规格 × 实际执行秒数 × 单价
             + 内存 GB × 实际执行秒数 × 单价
             + 调用次数费用 + 额外存储/网络费用
压测组输入必须记录目标
A15s / 720p / H.264混音耗时、峰值内存、输出大小测短视频基线
B60s / 1080p / H.264stream copy 成功率、成本典型客户素材
C60s / HEVC / VP9转码回退比例与耗时判断高成本路径
D300–600s 长视频临时磁盘、超时、并发等待判断是否需要分级规格

FC CPU 弹性实例按量调用的执行时间计费粒度为 1 毫秒，意味着可细粒度结算，但并不是按最终视频秒数直接计费。来源：函数计算按量付费。

05 / 已完成的验证和上线前风险

验证点状态说明

讲话区间合并本地通过过滤非 word、处理交叠、短暂停顿合并
FFmpeg 混音本地通过样例 15 秒视频产出 MP4；声音轨保留
已有音乐与手动区间本地通过没有 Key 仍能操作
ElevenLabs Video-to-Music / Scribe 真正付费调用待在线验证用户提供受限额度 Key，但本环境 DNS 不可用，真实 API 未请求
阿里云 FC / OSS 真实运行尚未部署当前仅提供协议、执行器及迁移计划

真正交付客户前至少补齐

  • 多人对话、短促语气词、背景音乐、多人重叠讲话场景的识别准确率与人工听评。
  • 纯音乐时不额外调用 Scribe；若已有独立配音轨，应优先使用 Sidechain，节省 STT 成本。
  • 网络超时、任务重试的幂等性；Scribe 和音乐生成结果可缓存，调参数只做 FFmpeg 重混。
  • 上传认证、用户额度限制、限流、任务清理、私有对象管理、用户内容合规与审计。
  • 音乐声压一致性、峰值限制、原始音轨已经包含 BGM 时的产品提示。
第一版与“音源分离”不同：Video-to-Music 用来生成新音乐，Scribe 只用于预测压低新音乐的讲话时间。若客户希望原视频已存在的背景音乐也自动变小，这是下一阶段的独立能力。
